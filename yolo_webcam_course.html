AI 視覺影像環境建置與 WebCam 基礎測試

🎯 本單元核心學習目標

  • 認識 OpenCV 基礎架構：理解 cv2.VideoCapture 底層如何對接系統相機硬體。
  • 事件監聽循環 (Event Loop)：掌握 cv2.waitKey(1) & 0xFF 鍵盤監聽與退出邏輯。
  • 影像截取與存檔：使用 cv2.imwrite() 將當前 Frame 寫入本機硬碟，自動以年月日時分秒命名。
  • 自學分流指引：簡老師提供專屬教學網頁，讓進度較快的同學能自主往前挑戰進階專題。

⚙️ 課堂實作步驟指引

  • 步驟 1：插入 USB 攝影機，確認相機驅動正常運作。
  • 步驟 2：使用下方 Prompt 1-1 引導 AI 生成基礎 WebCam 視窗程式。
  • 步驟 3：按下鍵盤 s 鍵測試拍照存檔，確認 captures/ 目錄自動產出照片。
  • 步驟 4：使用 Prompt 1-2 要求 AI 新增「每 5 秒定時拍攝」與「倒數計時」功能。
💡 實用 Prompt 1-1：WebCam 基礎串流與熱鍵拍照控制
你是一位精通 Python 與 OpenCV 的電腦視覺導師。請編寫一個適合初學者執行的 WebCam 串流視窗程式： 1. 自動開啟預設攝影機（索引 0），視窗尺寸設定為 640x480。 2. 畫面左上角以綠色字體即時顯示當前幀率（FPS）與當前時間。 3. 鍵盤熱鍵操作： - 按下鍵盤 's' 鍵手動拍照，將畫面存入同目錄下的 'captures' 資料夾，檔名格式為 'img_YYYYMMDD_HHMMSS.jpg'。 - 拍照成功時，畫面上顯示短暫 1 秒的『已成功拍照存檔！』綠色提示。 - 按下鍵盤 'q' 鍵安全釋放相機資源並關閉視窗。 4. 請提供完整可執行的 Python 腳本，包含清晰的中文註解。
📌 教師引導心法：先讓學生體驗按下鍵盤拍照的即時反饋，建立信心；程式若不合心意，引導學生「不要重寫，直接叫 AI 改」。
💡 實用 Prompt 1-2：定時縮時攝影 (Timelapse) 與例外防呆擴充
請在剛才的 WebCam 程式基礎上進行功能升級（請直接提供修改後的完整 Python 代碼）： 1. 新增【自動定時拍攝】功能：程式啟動後，每隔 5 秒自動拍一張照片並存入 'captures' 資料夾。 2. 畫面右上角顯示倒數計時秒數，提示使用者距離下一次自動拍攝還剩幾秒。 3. 增加例外處理：若相機被其他軟體佔用或找不到設備，請跳出友善視窗提示，嚴禁直接閃退報錯。 4. 按 'q' 鍵可隨時提早結束定時拍攝並安全關閉視窗。
📌 教師引導心法：讓學生觀察 AI 如何在舊代碼基礎上進行「增量修改 (Incremental Update)」，體會 AI 協作的高效率。
第 02 節課實戰

Prompt 提示詞工程、拍照控制與 1:1 畫面校正

▶ 觀看第 02 課影片 (YouTube)

💡 學生使用 AI 的最大障礙剖析

  • 不知道要跟 AI 說什麼：專業知識不足，只會說「幫我做相機」，得到過於簡陋的範例。
  • 缺乏結構化 Prompt：優秀的 Prompt 需涵蓋「身分角色、任務目標、輸入輸出細節、邊界限制」四層面。
  • 畫面拉伸變形問題：初學者習慣直接 cv2.resize()，導致人臉變扁變胖，失真嚴重。
  • Letterboxing 演算法：計算幾何長寬比，不足部分以黑邊填補，保持真實 1:1 比例。

⚡ 高低解析度分流之算力哲學

  • 1080p / 4K 的迷思：高解析度適合存檔與人眼看，但餵進 AI 模型會造成 FPS 暴跌。
  • 邊緣裝置限制：在一般筆電或樹莓派上，高解析度幾乎無法跑動 AI 即時推論。
  • 商用雙流架構 (Dual-Stream)：
    • 顯示與 AI 推論端：降採樣為 640x360 或 640x640（1/4 算力，維持 30 FPS）。
    • 存檔拍照端：觸發瞬間擷取 1080p 原始母幀存檔。

💡 實用 Prompt 2-1：1:1 防變形校正與即時亮度檢核視窗
你是一位精通 OpenCV 演算法的 Python 工程師。請設計一個 WebCam 控制視窗： 1. 畫面防變形校正：無論輸入鏡頭原始長寬比為何（如 16:9 或 4:3），在 800x800 固定視窗中，自動維持真實長寬比，不足處以黑色背景填補（Letterbox 等比縮放），不可將人物壓扁或拉寬。 2. 亮度智慧檢核：即時計算畫面中央區域平均亮度（0~255）。 - 若亮度 < 50，畫面顯示黃色警告：『環境過暗，請補充光源』 - 若亮度 > 205，畫面顯示紅色警告：『環境過曝，請調整鏡頭角度』 - 介於 50~205，顯示綠色：『光線良好』 3. 按 's' 鍵拍照、'q' 鍵離開，程式碼需包含完整的防呆容錯處理與中文註解。
📌 教師引導心法：讓學生拿手電筒照射鏡頭或以手遮擋，親眼驗證 AI 演算法對過亮/過暗的即時檢測響應。
💡 實用 Prompt 2-2：推論與存檔分離之高低解析度雙流架構
請將 WebCam 相機程式升級為商用『雙解析度分流架構』： 1. 影像輸入端維持 WebCam 硬體最高可用畫質（例如 1920x1080）。 2. 即時預覽顯示與 AI 模型輸入端，自動降採樣至 640x360（1/4 運算量），確保 FPS 穩定維持在 30 幀以上。 3. 當使用者按下 's' 觸發拍照時，系統自動擷取 1920x1080 高解析度原始母幀存檔，兼顧流暢度與高清晰度。 4. 在視窗左上角對比顯示【原始解析度】vs【運算解析度】與即時延遲（毫秒 ms）。
📌 教師引導心法：這是樹莓派或嵌入式 AI 邊緣裝置開發的核心架構，讓學生明白演算法必須兼顧硬體算力平衡。

🖥️ 1920x1080 四宮格座標換算

  • 螢幕解析度規格：標準顯示器為 1920x1080。
  • 四宮格數學劃分：寬高各除以 2，每個宮格為 960x540。
  • NumPy 陣列拼接：透過 np.hstack 與 np.vstack 把 4 個 Frame 拼為單一完整晝面。
  • 多鏡頭頻寬競爭：4 個畫面同時傳輸傳輸量極大，關閉 1~2 格可使主畫面 FPS 回升至 30。

🎥 雙實體攝影機 (Dual WebCam) 整合實務

  • 多執行緒 (Threading) 防凍結：雙鏡頭初始化耗時不同，必須用線程非同步取幀，避免畫面停頓。
  • 滑鼠動態互動：點擊任一宮格，該畫面自動放大為單一全螢幕；再點一下恢復四宮格。
  • 鏡頭主題互換：按快捷鍵將「鏡頭 1」與「鏡頭 2」的顯示位置瞬間對調。
  • 產業趨勢感悟：簡老師分享業界 AI 開發速度是傳統的 5~10 倍，懂得反問與整合才是核心能力。

💡 實用 Prompt 3-1：四宮格 (2x2) 多分割監控畫面與動態切換
請使用 Python、OpenCV 與 NumPy 開發一個【四宮格多分割監控展示系統】： 1. 建立一個 1920x1080 視窗，分割為 2x2 四個宮格（每格尺寸精確為 960x540）： - 宮格 1：原始彩色相機串流 - 宮格 2：灰階濾鏡處理畫面 - 宮格 3：Canny 邊緣偵測畫面 - 宮格 4：色彩反相或夜視效果濾鏡 2. 支援滑鼠互動：滑鼠左鍵點擊任一宮格，該宮格瞬間切換為全螢幕單一視窗；再次點擊恢復四宮格。 3. 鍵盤 '1'~'4' 可獨立切換各宮格的運算開關，關閉時顯示黑底『頻道暫停』，以降低 CPU 負載提升流暢度。
📌 教師引導心法：若學生只有一支攝影機，先用不同影像濾鏡模擬 4 通道，體驗保全監控系統的拼接原理。
💡 實用 Prompt 3-2：雙實體攝影機 (Dual WebCam) 讀取與鏡頭對調
請擴充上述系統為【雙實體攝影機 (Dual WebCam) 即時監控系統】： 1. 同時偵測並開啟系統中的兩支 USB 攝影機（WebCam 0 與 WebCam 1）。 2. 使用 Threading（多執行緒）非同步讀取兩個鏡頭的影像，防止因鏡頭初始化或訊號延遲造成程式卡死。 3. 將兩支鏡頭畫面並排或放入四宮格中，確保等比例縮放不失真。 4. 實作『鏡頭對調功能』：按下鍵盤 'x' 鍵，鏡頭 1 與鏡頭 2 的顯示位置瞬間對調。 5. 若系統只偵測到一支相機，自動退回單鏡頭模式並給予文字提示。
📌 教師引導心法：可讓隔壁兩位同學互相借用相機插在同一台主機，體驗真實雙視角保全安防系統。
第 04 節課實戰

YOLO 骨架追蹤、多人跌倒警示與手勢拍照專題實作

▶ 觀看第 04 課影片 (YouTube)

🦴 YOLO Pose 骨架與手勢幾何邏輯

  • 17 個人體關鍵點：鼻子、雙眼、雙耳、雙肩、雙肘、雙腕、雙髖、雙膝、雙踝。
  • 螢幕座標特性：左上角為 (0,0)，Y 軸朝下（數值越小代表位置越高）。
  • 舉右手拍照：右腕 Y < 右肩 Y（手腕高過肩膀）。
  • 雙手平舉錄影：雙手腕高度與雙肩接近，且水平展開寬度大於身體寬度。

🚨 多人主控者模式 ＆ 長者跌倒警報

  • 多人衝突痛點：多人在鏡頭前若皆可觸發手勢，會造成系統嚴重混亂。
  • 中央主控者 (VIP) 機制：演算法選取最接近畫面正中心的人作為唯一主控者。
  • 跌倒判定準則：
    • 邊界框寬度明顯大於高度（橫躺形態）。
    • 頭部或軀幹重心 Y 座標急劇驟降。
  • 警報回饋：視窗邊框閃爍粗紅框、發出嗶聲警示並自動截圖存證至 fall_alerts/。
動作模式 幾何判定演算法 觸發行為與防護機制
舉右手拍照 right_wrist.y < right_shoulder.y 觸發拍照存檔，並啟動 3 秒 Cooldown 冷卻時間防連拍
雙手平舉錄影 雙手腕 Y 與雙肩 Y 相差 < 門檻且持續 1.5 秒 切換錄影狀態，右上角閃爍紅色『● REC』
中央主控者模式 計算每個人中心與畫面中心 (W/2, H/2) 之歐幾里得距離 距離最小者頭頂標示金色『★ 主控者』，只有他具備手勢控制權
多人跌倒急救警報 bbox_width > bbox_height * 1.3 且 hip.y > 地面門檻 視窗全螢幕閃爍紅框，跳出跌倒警報並自動儲存事件截圖
💡 實用 Prompt 4-1：YOLO Pose 骨架手勢互動（舉手拍照 / 平舉錄影）
請使用 Python、Ultralytics YOLO Pose 模型（yolo11n-pose.pt 或 yolov8n-pose.pt）與 OpenCV 開發手勢控制相機： 1. 即時偵測人體 17 處骨架關鍵點並繪製骨架連接線。 2. 手勢辨識一【舉右手拍照】： - 當偵測到右手腕高度高於右肩/右眼時，自動觸發拍照存檔。 - 必須加入 3 秒防連拍冷卻時間（Cooldown），在畫面上顯示倒數圓形進度條。 3. 手勢辨識二【雙手平舉錄影】： - 當雙手手腕平舉與肩膀同高且維持 1.5 秒時，切換『開始/停止錄影』。 - 錄影中右上角閃爍紅色『● REC』字樣，檔案存為 MP4。 4. 文字標籤一律採用微軟正黑體繁體中文。
📌 教師引導心法：提醒同學後退 1.5 ~ 2 公尺，確保上半身完整入鏡；相機務必架腳架固定，切忌手持晃動。
💡 實用 Prompt 4-2：中央主控者鎖定 ＆ 多人跌倒全螢幕紅框警報
請將上述 YOLO Pose 系統擴充為【多人智慧安防與照護系統】： 1. 【畫面中央主控者鎖定】： - 當畫面中有多人時，計算所有人邊界框中心點，鎖定離畫面正中央最近的人為【主控者 (VIP)】。 - 主控者頭頂標註金色『★ 主控者』框，唯有此人的舉手動作能觸發拍照或錄影。 2. 【多人跌倒急救警報】： - 全局監控畫面中所有人員。若任何一人人體外框呈現橫躺狀態（寬度顯著大於高度）且重心驟降，立即觸發【跌倒警報】！ - 觸發時視窗外框閃爍粗紅色警示框，畫面中央顯示『🚨 偵測到人員跌倒！』，並自動截圖存證至 'fall_alerts' 資料夾。
📌 教師引導心法：讓同學模擬假裝滑倒或趴下，觀察 AI 能否在多人同框中精準捕獲跌倒事件，體會專題商品化測試流程。
