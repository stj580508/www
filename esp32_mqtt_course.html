第 01 節課實戰

ESP32 環境建置、BME 感測器與 OLED 顯示

▶ 觀看第 01 課影片 (YouTube)

🎯 本單元核心學習目標

  • 代理人免打擾設定：設定 Custom 權限、Allow 與 Always Proceed，讓 AI 能自主測試指令。
  • 硬體插拔防呆：排針與 Type-C 平行用力，絕不可往上折撩，保護實驗板。
  • BME280 晶片特性：能同時量測溫度 (°C)、相對濕度 (%) 與大氣壓力 (hPa)。
  • I2C 匯流排並聯：ESP32 GPIO 22 (SCL)、GPIO 21 (SDA) 可同時掛載 BME280 (0x76) 與 OLED (0x3C)。

🔌 接線腳位配置清單

  • BME280 SCL / SDA ➔ ESP32 GPIO 22 / GPIO 21
  • OLED SCL / SDA ➔ 並聯至 GPIO 22 / GPIO 21
  • 電源供應 ➔ VCC 接 3.3V，GND 接接地腳位
  • 課堂檢測指標：OLED 螢幕上穩定輪播 Temp 23.7°C、Humi 45.6%、Pres 994.1 hPa。
💡 實用 Prompt 1-1：陌生感測模組快速探索與接線引導
我手邊有一顆陌生的感測模組，上面標示『BME』，腳位有 VCC, GND, SCL, SDA。 請扮演資深物聯網硬體導師： 1. 告訴我這顆感測器主要能測量哪些物理量？（例如溫濕度、大氣壓力） 2. 我使用的是 ESP32 實驗板，請告訴我如何將它與 I2C 腳位（GPIO 21, 22）進行實體接線？ 3. 請使用 MicroPython 撰寫一段簡單的掃描 I2C 位址（i2c.scan()）與數值讀取測試代碼。
📌 教師引導心法：拿到任何未知零件時，第一時間向 AI 詢問引腳與原理，不需死背資料手冊。
💡 實用 Prompt 1-2：BME280 數值讀取並以 OLED 螢幕即時顯示
請替 ESP32 撰寫 MicroPython 程式： 1. 同時驅動 BME280 感測器與 0.96 吋 SSD1306 OLED 螢幕（兩者皆接在 I2C: SCL 22, SDA 21）。 2. 每隔 1 秒讀取一次環境數值，並在 OLED 螢幕上清晰顯示三行數據： - 第一行：『Temp: XX.X C』 - 第二行：『Humi: XX.X %』 - 第三行：『Pres: XXXX.X hPa』 3. 包含完整例外防呆機制（若讀取失敗顯示 'Sensor Error'，不可當機閃退）。
📌 教師引導心法：讓學生親自體驗 I2C 兩條線同時掛載多個週邊裝置的簡潔優勢。
第 02 節課實戰

四按鈕碼表電路 ＆ MQTT 雲端智慧控制

▶ 觀看第 02 課影片 (YouTube)

⏱️ 四按鈕碼表低電位動作設計

  • 低電位動作 (Active Low)：按鍵未按下為 High (3.3V)，按下時導通接地為 Low (0V)。
  • 腳位分配：PB1 (14), PB2 (27), PB3 (26), PB4 (25)。
  • 按鍵功能：
    • PB1: 開始 / 暫停 (Start / Pause)
    • PB2: 計圈時間記錄 (Lap Time)
    • PB3: 歸零重設 (Reset)
    • PB4: 畫面模式切換

☁️ MQTT 雲端連線必抄三要素

  • Broker 伺服器：mqttgo.io（字元不可漏點打錯）。
  • 通訊埠 (Port)：1883（標準 TCP 協定）。
  • Client ID：自訂唯一名稱（建議加上座號避免同班踢除斷線）。
  • 手機 App：安裝 IoT MQTT Panel（免費房子圖示），建立按鈕 Publish 指令，並訂閱 Subscribe 狀態。
按鈕 / 週邊 ESP32 GPIO 電路模式 MQTT 主題 (Topic) 與行為
按鈕 PB1 GPIO 14 Input, PULL_UP 接收 / 發布 START / STOP 指令
按鈕 PB2 GPIO 27 Input, PULL_UP 記錄 LAP 圈數時間並推播至雲端
按鈕 PB3 GPIO 26 Input, PULL_UP 接收 / 發布 RESET 碼表歸零指令
按鈕 PB4 GPIO 25 Input, PULL_UP 切換 OLED 畫面與 MQTT 狀態輪播
💡 實用 Prompt 2-1：四按鈕低電位動作之 OLED 碼表控制
請替 ESP32 編寫一個功能完備的 MicroPython 碼表程式： 1. 硬體配置：0.96 吋 OLED (I2C: 21, 22)，四顆實體按鈕接在 GPIO 14, 27, 26, 25（啟用內部 PULL_UP，低電位觸發）。 2. 按鈕邏輯： - PB1 (GPIO 14)：開始計時 / 暫停計時 - PB2 (GPIO 27)：記錄當前圈數時間 (Lap Time) - PB3 (GPIO 26)：碼表歸零 (Reset) - PB4 (GPIO 25)：切換主畫面與歷史圈數列表 3. 需具備軟體防彈跳 (Debounce) 機制，確保按鍵靈敏且不重送，以毫秒精度即時刷新螢幕。
📌 教師引導心法：提醒同學理解內部上拉電阻（Pin.PULL_UP）的意義，不需額外焊接實體上拉電阻。
💡 實用 Prompt 2-2：ESP32 連線 MQTT (mqttgo.io) 與手機 App 雙向遙控
請編寫 ESP32 MicroPython 程式，結合 Wi-Fi 與 MQTT 協定： 1. 連線至 Wi-Fi（指定 SSID 與 Password），連線成功後在 OLED 顯示配發的 IP。 2. 連接至 MQTT 伺服器：Broker 為 'mqttgo.io'，Port 為 1883，Client ID 為 'esp32_iot_node'。 3. 訂閱主題 'school/esp32/cmd'： - 收到 'START' 啟動碼表計時 - 收到 'STOP' 停止計時 - 收到 'RESET' 碼表歸零 4. 發布主題 'school/esp32/status'：每秒將當前碼表時間推播回 MQTT，供手機端即時顯示。 5. 提供完整代碼與手機 IoT MQTT Panel 儀表板設定指引。
📌 教師引導心法：手機在雲端按按鈕，遠端的 ESP32 馬上同步動作，讓學生親身體會物聯網魅力！
第 03 節課實戰

AI 視覺影像辨識初探與五步驟 SOP

▶ 觀看第 03 課影片 (YouTube)

👁️ 視覺實作五步驟標準 SOP

  • 步驟 1：確認 USB 鏡頭接好，檢查 Python OpenCV 環境。
  • 步驟 2：按 1 切換物件偵測 (80類)、按 2 切換骨架姿勢 (17點)、按 3 切換去背分割。
  • 步驟 3：即時統計分類總數（人、桌子、椅子、筆電、水杯）。
  • 步驟 4：看不懂英文報錯不要怕，直接截圖貼回給 AI (Screenshot Debug)。
  • 步驟 5：發想競賽專題（如手勢求救、視障避障導航、門禁人流統計）。

💡 簡老師的 AI 開發箴言

  • 「我只動嘴巴就好了」：有想法與架構，動嘴巴描述，AI 就會寫出程式碼。
  • 算力與解析度取捨：一般電腦多核心跑得順，若移植到小板子絕對不要開高解析度。
  • 不要閉門造車：先看別人做過的專題，拿別人的架構修改為自己的方法。
  • 專案商品化思維：從身邊實際需求切入，打造具備實用價值的完整系統。
💡 實用 Prompt 3-1：OpenCV + YOLO11 三合一模式切換與繁體中文標籤
請使用 Python、OpenCV 與 Ultralytics YOLO11 開發即時 WebCam 視覺程式： 1. 自動開啟相機串流，並支援鍵盤熱鍵動態切換三種模式： - 按 '1'：通用物件偵測模式（yolo11n.pt），偵測 80 種常見物品 - 按 '2'：人體姿態骨架模式（yolo11n-pose.pt），繪製 17 處關節點骨架 - 按 '3'：實例分割模式（yolo11n-seg.pt），繪製物體輪廓多邊形遮罩 2. 畫面文字標籤必須使用系統微軟正黑體顯示【繁體中文】（如：人、椅子、瓶子、筆記型電腦）。 3. 畫面左上角顯示當前模式名稱與即時 FPS 幀率，按 'q' 鍵退出。
📌 教師引導心法：讓學生感受 3 種不同 AI 模型的視覺效果，理解物件、骨架與分割在應用場景上的差異。
💡 實用 Prompt 3-2：現場物件分類數量即時統計看板
請在上述 YOLO 辨識程式中新增【物件分類總數即時統計面板】： 1. 即時遍歷畫面中所有被偵測到的物件，統計各類別的出現數量（例如：人 x 5, 椅子 x 8, 杯子 x 2, 螢幕 x 3）。 2. 在畫面右上方半透明資訊欄中，由多到少即時列出統計清單與畫面總物件數。 3. 當偵測到『人』的數量發生變化時，在終端機印出警示日誌。 4. 代碼需優化推論速度，避免因統計運算導致畫面掉幀。
📌 教師引導心法：引導學生思考人流計數、商場客群分析等商業專案應用。
